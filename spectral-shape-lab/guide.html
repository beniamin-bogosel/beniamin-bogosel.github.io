Explore. Optimize. Keep the shape.

The app learns geometry through a ten-output Dirichlet spectrum. Everything runs in your browser; your imported models, formulas and results stay on your computer.

Run an optimization

  1. Choose a preset or enter your own formula using x1 through x10.
  2. Select minimization or maximization, a fixed area, starting-shape count and step budget.
  3. Click Start optimization. The plot shows the current shape and best candidate; the history tracks the raw objective F.
  4. Use Pause, Resume or Stop. The best candidate remains available.
  5. Save a complete Run JSON, physical Fourier Coefficients CSV, or a vector/raster image (SVG/PNG). Downloads also work during a run, giving a snapshot.

Write a new functional

You are not limited to the saved functions. Polynomials, arithmetic and elementary functions are supported; the app differentiates your formula symbolically and applies the neural chain rule.

x5 + 0.5*x6
(x6-x5)^2
x6/x1 + 0.01*log(x10)
x5^2/x1 + exp(x2/100)

Use + - * / ^, parentheses, pi, e, and sin cos tan asin acos atan sinh cosh tanh exp log ln sqrt. Write 2*x5, not 2x5. Functions take one parenthesized argument. Arbitrary code, indexing, assignments and nonsmooth operators such as abs or max are rejected.

The variables are eigenvalues at the requested area. Area scaling occurs before evaluating F, including for nonlinear functions. F may be negative or zero. Save formula keeps it in this browser; edit objectives.json to add a preset for everyone using your deployed app.

Your formula and its partial derivatives must be real, finite and C¹ over the spectra you intend to explore. The starting disk must be in their domain. Invalid trial points trigger backtracking. The app cannot prove regularity, guarantee PDE accuracy, or eliminate the piecewise nature of ReLU gradients.

Replace the network

Replace model loads a local .spectral.json bundle. It is not uploaded. The model dimensions, ensemble, normalization, harmonic count, all ten output identities, constraints and training support travel together in this file.

In the research project's Python environment, export another saved model with:

python -m spectral_shape.export_browser \
  --models results/my_ten_output_model \
  --out web/models/my_model.spectral.json \
  --name "My ten-output model"

The exporter uses saved checkpoints and training/split metadata; it performs no PDE solves. Version 1 supports dense ReLU/tanh/SiLU models with all ten outputs. Unsupported heads or inconsistent arrays are rejected. The supplied model includes all 14,000 training shapes needed for starts and support checks, so the complete bundle is about 7.3 MB.

What stays constrained?

Every accepted shape has the requested analytic area. Fourier amplitudes and per-harmonic caps are projected. For the supplied model, r(θ) ≥ 0.25 a₀ > 0 at every angle, so the radial boundary cannot self-intersect. A compact nearest-neighbor search preserves the full training-support orbit with a conservative numerical margin.

The best candidate is selected using predicted F only. Displayed eigenvalues are not sorted afterward; the app reports output inversions. Neither ensemble spread nor training-support membership certifies prediction accuracy near an optimized shape.

Run locally or publish on GitHub Pages

Serve the source app from the project root:

python3 -m http.server 8000 --bind 127.0.0.1 --directory web

Open http://localhost:8000/. This is a static file server, not a computation backend. Directly opening index.html with file:// will encounter browser restrictions on modules and workers.

For publishing, assemble the static files with:

node web/scripts/build.mjs

Publish the contents of web/dist/ to a Pages repository or branch. Relative asset paths support username.github.io/repository/. No Python, Node, API or FreeFem process is needed on the host.

A GitHub Pages workflow example is included. Copy it to .github/workflows/spectral-pages.yml in the source repository, select GitHub Actions as the Pages source, and run the workflow manually. It is not enabled automatically.

Numerics, modules and verification

The full technical README describes the bundle schema, forward/backward operations, symbolic parser, support search, numerical tolerances and reproduction commands. The runtime has no external package or CDN dependencies. The UI, model evaluation, expressions, geometry, optimizer, support and plotting live in separate modules under src/.

Tests compare the browser engine against PyTorch values and all ten input Jacobians, Python projections and support distances. Browser tests exercise live runs, pause/stop, all downloads, replacement models, invalid input and mobile layout.
